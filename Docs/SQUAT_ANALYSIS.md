# 深蹲阶段与次数：本步成品验收

本步在现有双摄动捕和脚部接地功能上增加深蹲阶段、完整次数、开始/暂停/清零面板。先验收这一项，再推进导出与比赛材料。

## 打开并运行

1. 用 Unity 2022.3.62f3c1 打开本次任务工作树的 unity 项目，打开 Assets/动捕.unity。不要用原始项目验证新面板。
2. 启动配对 Python 工作树中的 run_squat_analysis.bat，选好前摄和侧摄，使用当前已保存的标定配置并启动采集。前摄 UDP 8888，侧摄 UDP 8889。
3. Unity 点击 Play。保持双脚接地站直，等待现有驱动建立站立基准。
4. 在右上角“深蹲运动分析”点击“开始 / 继续”。站直确认后连续做 5 次深蹲，每次回到站直位置稍停。
5. 完整次数应依次变为 1、2、3、4、5。暂停保留已完成次数；清零后需要重新点击开始。

动捕场景已安装组件。其他场景可选中带 HumanoidPoseDriver 的人物，执行菜单 Mocap > Install Squat Analysis Panel，并保存场景。

## 本次计数规则

- 膝屈曲角 = 180° - 现有驱动的膝内角；站直约 0°。
- 初始站直：双膝屈曲角均 ≤15°，持续 0.25 秒。
- 动作开始：双膝均 ≥25°，持续 0.10 秒。
- 达到最低深度：双膝均 ≥45°，持续 0.10 秒。随后双膝均站直并持续 0.25 秒才计一次。
- 底部显示阈值为 65°，回升使用 4°方向滞回。阶段标签用于演示，不是精细生物力学分期。
- 两腿关键点必须齐全且各自可见度 ≥0.65；站立基准、下蹲和脚部接地必须已开启。
- 帧龄超过 250 毫秒、姿态帧停止推进、缺失关键点、时间倒退或捕获时间间隔超过 0.5 秒时，未完成动作会作废，恢复后先站直重新确认。
- 使用捕获时间；重复渲染帧不累计确认时长。只抬一条腿不会满足双膝深度条件。

阈值可在人物的 SquatAnalysisController 中调整；调整后重新进入 Play。先保持默认值完成一次验收，漏计时先看面板提示与双腿是否入镜。

## 最小现场验收

| 操作 | 预期 |
| --- | --- |
| 站直、开始、连续完整深蹲 5 次 | 完整次数为 5；站立/下降/底部/上升可见 |
| 站直等待或在底部停留 | 次数不会持续增加 |
| 轻微屈膝，未达到双膝最低深度 | 不增加次数 |
| 深蹲途中暂停或遮挡腿部，然后站直恢复 | 不补计被中断的那一次；此前完整次数保留 |
| 清零后重新开始 | 显示 0，站直确认后可再次计数 |

首次验收建议在 Python GUI 同时录制姿态。回放同一段 5 次动作有助于复查；录制文件留在本地 recordings/，不进 Git。

## 指标与验证边界

面板角度来自现有动捕驱动的计划腿方向，是几何估计，不是独立实测关节角。当前模型骨盆位移受骨架与 IK 限制，不能直接当成人体真实厘米位移；本步不输出力、关节力矩或功率。

自动测试验证计数规则及中断处理，Unity 编译和场景安装验证接入。摄像头、遮挡、站位与角度估计的实际效果，仍须完成上表现场验收后确认。

## 代码入口

- Assets/SquatAnalysis/Core/SquatCycleCounter.cs：不依赖 Unity 的阶段与计数状态机。
- Assets/SquatAnalysis/Runtime/SquatAnalysisController.cs：读取现有姿态帧，进行有效性检查。
- Assets/SquatAnalysis/Runtime/SquatAnalysisOverlay.cs：右上角控制面板。
- Assets/Editor/SquatAnalysisSetup.cs：场景安装菜单与批处理入口。
- Assets/SquatAnalysis/Tests/EditMode/：计数规则的 EditMode 测试。

新组件只读取现有驱动，不写人物骨骼，也不创建 MediaPipe 处理器。
